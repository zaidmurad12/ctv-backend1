# Provider Architecture
## CTV Platform Engineering Specification

Version 1.0

---

# Purpose

This document defines the Provider Architecture used by CTV Platform.

Providers are responsible only for communicating with external systems.

Business logic MUST NEVER exist inside Providers.

Providers must remain isolated from the Core.

---

# Definition

A Provider is an adapter between CTV Platform and an external content source.

Examples

• Cinemana
• TMDB
• Jellyfin
• Plex
• Future APIs

---

# Core Principle

Core does not know Cinemana.

Core does not know TMDB.

Core only knows ProviderInterface.

# Responsibilities

Providers may

✔ Authenticate

✔ Send Requests

✔ Parse Responses

✔ Map External Objects

✔ Handle Provider Errors

✔ Report Health

Providers must NOT

✖ Apply Business Rules

✖ Save Database

✖ Call Prisma

✖ Cache Business Data

✖ Execute Synchronization

✖ Know Android

✖ Know Backend Controllers

---

# Provider Interface

Every Provider MUST implement the following interface.

```typescript
interface ProviderInterface {

    health()

    discover()

    search()

    movie()

    show()

    season()

    episode()

    streams()

    subtitles()

}
```

# Provider Registration

Providers are registered using Dependency Injection.

Providers are never instantiated manually.

# Provider Discovery

The system automatically discovers all registered providers.

No provider names should be hardcoded.

# Data Mapping

Providers return External DTOs.

Core converts them into Domain Models.

External Models never enter the Database directly.

---

# Error Handling

Providers never throw raw HTTP errors.

They return standardized ProviderResult objects.

Possible Errors

Timeout

Unauthorized

Forbidden

Not Found

Rate Limited

Invalid Response

Unknown Error

---

# Authentication

Every provider manages its own authentication.

Authentication logic never leaves the Provider.

# Provider Rules

Every Provider MUST

Implement ProviderInterface.

Be stateless.

Be independently testable.

Be replaceable.

Be isolated.

Support Dependency Injection.

Never access Prisma.

Never access Android.

Never access Controllers.

Never import another Provider.

---

# Future Expansion

The platform should support adding a new provider by creating a single new folder inside

providers/

without modifying any Core module.
