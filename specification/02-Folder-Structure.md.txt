# Folder Structure
## CTV Platform Engineering Specification

Version 1.0

---

# Purpose

This document defines the official repository structure of the CTV Platform.

Every file in the project must belong to one of the directories defined in this document.

No folder should be created unless explicitly approved by the architecture documentation.

# Naming Convention

Folders

lowercase

Example

```
providers

backend

scheduler
```

---

Files

camelCase

Example

```
movieService.ts

searchController.ts
```

---

Classes

PascalCase

Example

```
MovieService

CatalogImporter

SearchEngine
```

---

Interfaces

Prefix I

Example

```
IProvider

IMovieRepository
```

---

Enums

Suffix Enum

```
MovieStatusEnum

ProviderTypeEnum
```

---

DTO

Suffix Dto

```
CreateMovieDto

SearchMovieDto
```

---

Repository

Suffix Repository

```
MovieRepository
```

---

Service

Suffix Service

```
SearchService

SubtitleService
```

---

Controller

Suffix Controller

```
MovieController
```

---

Module

Suffix Module

```
MovieModule
```

# Folder Rules

Every module must own its files.

Cross-module imports are allowed only through public interfaces.

No circular dependencies.

No business logic inside controllers.

No Prisma usage outside repositories.

Providers never communicate with each other.

Core never imports Provider implementations.

Android never communicates directly with Providers.

Admin never communicates directly with Providers.

All communication happens through Backend API.
