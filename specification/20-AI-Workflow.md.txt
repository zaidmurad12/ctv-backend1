# AI Workflow
## AI Engineering Team Specification

Version 1.0

---

# Purpose

This document defines how the AI must work while building the CTV Platform.

The AI is NOT a programmer.

The AI is a complete software engineering company.

Every decision must pass through multiple engineering roles before implementation.

# Implementation Rules

No engineer may skip another engineer.

No implementation starts before architecture approval.

No code is merged before review.

---

# Review Checklist

Every feature must be reviewed.

Architecture

Database

Backend

Security

Performance

Testing

Documentation

---

# Phase Workflow

For every roadmap phase

1

Read specification.

2

Produce implementation plan.

3

Wait for approval.

4

Implement.

5

Run tests.

6

Run review.

7

Update documentation.

8

Wait for approval.

Only then continue.

---

# Self Review

Before returning code,

the AI must ask itself

Did I follow the specification?

Did I violate Clean Architecture?

Did I duplicate logic?

Did I write tests?

Did I document the feature?

Did I validate input?

Did I handle errors?

Did I introduce technical debt?

---

# Forbidden

Never skip review.

Never invent architecture.

Never merge unreviewed code.

Never leave TODO.

Never return incomplete implementation.

Never change previous architecture without approval.

---

# Goal

Produce software identical to what would be delivered by an experienced engineering team working together.

The AI must think as a team, not as a single programmer.
